# 중1 과학 도해(코드로 굽는 디테일 그림)

개념 스텝("과학 용어 정복하기")과 정리 카드의 자세히(`more`)에 싣는, 실제 과학 내용을 담은 그림이다(2026-11-15, 32장).
스틱맨 비유 컷(`qa/sketch`)과는 따로다. 이미지 생성 모델과 발주를 쓰지 않고 코드로 그려 래스터로 굽는다.

## 구조

| 파일 | 맡은 일 |
|---|---|
| `build.mjs` | 그림을 굽는다. 헤드리스 크롬에 가짜 주소(`http://fig.local`)로 저장소 파일을 물리고, 그림 칸을 `meta.scale`배로 찍어 PNG를 만든 뒤 webp로 바꾼다 |
| `lib/kit.js` | 그리기 도구(브라우저에서 돈다): SVG 층과 그라데이션, 라벨과 지시선, 흐름 화살표, 잡음, 고르게 흩뿌리기, 보로노이 칸, three.js 무대(`three`), 회전체 단면(`latheCut`), 도감식 렌더(`renderIllus`), 그림자 판, 질감 읽기 |
| `lib/cell.js` | 세포 그림 공용(u2l2f1, u2l2f2, u2l9f1): 세포 재질, 잘린 캡슐(마이토콘드리아, 엽록체), 쐐기로 자른 핵, **세포 안 빈자리 찾기(`placer`: 막 안에 들고 서로 겹치지 않는 자리만, 못 찾으면 멈춘다)** |
| `lib/phasecurve.js` | 가열 곡선과 냉각 곡선 + 입자 창 다섯(u4l5f1, u4l6f1 공용, 평평한 구간은 완전히 수평) |
| `lib/syringe.js` | 세운 주사기와 입자(u6l2f1, u6l4f1 공용): 입자를 기체 칸에 고르게, 꼬리가 벽을 뚫지 않게, 누르개는 늘 통 위 |
| `figs/<키>.mjs` | 그림 하나. `meta`(크기, 배율, 품질, 바탕색)와 `draw(root, kit)`를 내보낸다 |
| `figs/<키>.md` | 그 그림의 검산 메모: 자리, 근거(레슨 글과 랩의 약속), 담은 과학 사실과 수치, 일부러 뺀 것 |
| `check-app.mjs` | 앱에 실린 그림을 폰(390×700)과 넓은 화면(1180×760)에서 열어 본다 |
| `tools/` | 조사 도구(단원 글 덤프, 참고 PDF의 쪽 이미지 뽑기), PNG를 webp로 바꾸는 도구 |

앱 쪽은 `src/content/sciFigG1.ts` 하나다. 표 `FIGS`에 그림마다 설계 크기, 대체 글, 캡션을 적고(글의 정본),
개념 스텝에는 `sciFig("u2l5f1")`(figure 블록), 정리 카드의 자세히에는 `sciFigMore("u7l5f1")`(그림과 캡션 HTML)를 넣는다.
키는 `u<단원>l<레슨>f<번호>`. 결과물은 `public/scifig/g1/<단원>/<키>.webp`(생성물, 손으로 고치지 않는다).

## 다시 그리기

```
node qa/scifig-g1/build.mjs                 # 모든 그림
node qa/scifig-g1/build.mjs u7l5f1 u4l4f1   # 고른 그림만
node qa/scifig-g1/build.mjs u7l5f1 --png-only   # public 에 쓰지 않고 검수용 PNG만
```

- 검수용 원본 PNG는 `../output/sci-figures/g1/png/<키>.png`(저장소 밖, `SCIFIG_PNG`로 바꿀 수 있다).
- 라벨은 Pretendard를 CDN에서 읽어 그림과 함께 굽는다(`<img>`로 싣는 SVG는 웹 글꼴을 못 쓰기 때문). 글꼴을 못 읽으면 빌드가 경고한다.
- 크롬은 시스템 크롬(`channel: "chrome"`)을 쓰고, WebGL은 실제 GPU로 돈다.
- 그림 크기를 바꾸면 `sciFigG1.ts`의 `w`, `h`도 같이 바꾼다(로드 전에 자리를 잡는 비율).
- 그림 코드가 `console.log("placed …")`나 `"proj …"`로 찍은 검산 값(입자 수, 길이 비, 넓이 부호 등)을 빌드가 그대로 보여 준다. 고친 뒤에는 이 값부터 본다.

## 화풍

- **입체로 렌더하고 도감처럼 마무리한다**: three.js 장면에 왼쪽 위 키라이트, 하늘과 바닥 반사광, 스튜디오 환경 반사.
  `kit.renderIllus`가 주변광 가림(GTAO)과 **재질 색을 어둡게 한 윤곽선**을 얹는다(검은 외곽선이 아니라 그 자리 색의 짙은 선).
  평면 아이콘이나 균일한 검은 선은 쓰지 않는다. 평면이 더 정확한 그림(흐름 지도, 단면 도표, 별 자취)은 SVG로 그리되 그라데이션과 반짝임을 준다.
- 바탕은 흰색(카드와 같다). 우주 그림은 짙은 남색 하늘(별은 옅게). 흰 바탕을 지키려고 톤 매핑을 끈다(`tone: "none"`가 기본).
- 라벨: 설계 폭 340px에서 **13px 이상**(`kit.MIN_FONT`, kit의 text와 label, 그림마다의 글자 도우미가 이보다 작은 크기를 13으로 올린다).
  폰(390 폭)에서 그림은 약 313px로 줄어 0.92배가 되므로 13px이어야 12px 이상으로 보인다. 흰 할로(어두운 바탕은 바탕색 할로), 가는 지시선 끝에 흰 테 두른 점.
  글자를 키우면 오른쪽 끝이 잘리기 쉽다: 빌드 뒤 그림 가장자리 두 줄에 짙은 화소가 있는지 본다(가운데 맞춤 글은 줄을 나누거나 반대쪽으로).
  앵커는 3D 점을 화면에 투영해서 잡는다(`st.project`). 이름표가 그림과 겹치면 자리를 코드로 고르게 한다(u7l4f1의 방위 표지).
- 천체의 겉은 그리지 않는다. `public/textures`(Solar System Scope, CC BY 4.0)의 실사 질감을 공에 입혀 빛으로 비춘다. 태양만 사진(`photos/sun_whitelight.jpg`, 원판 가운데 (918, 852), 반지름 723px).
- 화살표 색은 그 단원 랩의 약속을 따른다(Ⅲ: 복사는 곧은 주황 점선, 대류 고리는 오르는 쪽 주황과 내려오는 쪽 파랑, 전도는 뜨거운 쪽 붉은색에서 먼 쪽 주황. Ⅴ: 미는 힘 파랑, 되돌리는 힘과 중력 빨강, 떠받치는 힘과 운동 방향 초록. Ⅳ: 들어갈 카드의 짝 색(융해·응고 파랑, 기화·액화 산호, 승화 보라. 가열과 냉각의 뜻은 싣지 않는다). Ⅵ: 기체 입자 #5AA2F8, 샤를은 랩의 온도 색).
- 크기: 설계 폭 340, 높이는 400 안. 3배로 구워 1020px 폭, webp 품질 86~88에서 한 장 20~60KB(별 자취만 116KB).

## 정확하게 그리는 법(식에서 나오게)

- 방향과 개수를 손으로 정하지 않는다. 별 자취와 천구는 별의 방향 s(δ, H) = cos δ (cos H·m + sin H·W) + sin δ·p(위도 37°)에서, 화살표도 같은 식의 길 한 토막에서 나온다.
- 같아야 하는 것은 코드가 확인하고 어긋나면 멈추게 한다: 창마다 입자 수, 화살표 길이 비, 꼬리 길이, 주사기 기둥 높이(4 : 2 : 1, 28 : 30 : 36), 북쪽 원의 화면 넓이 부호(시계 반대), 접선과 중심 방향의 내적 0.
- 크기 비는 실제 값으로(행성 적도 반지름, 극이 눌린 정도, 고리 반지름, 달 그림자와 지구 그림자 비 2.7배). 과장하면 그림 안에 적는다.

## 그릴 때 걸렸던 것

- 정사영 카메라의 먼 평면이 200이면 400 떨어진 물체가 잘려 아무것도 안 보인다(kit은 5000으로 둔다).
- `ShaderPass`는 uniform을 복제하는데 렌더 타깃 질감은 복제되지 않아 비워진다. 질감은 패스를 만든 뒤에 넣는다(`renderIllus`).
- 상자 여섯 면이 같은 질감이면 세포 하나에 핵이 둘로 보인다. `RoundedBoxGeometry`는 앞면 재질에만 핵을 그린다.
- 한 쌍의 화살표(기화와 액화처럼)에 이름을 붙일 때 이름이 서로 뒤바뀌기 쉽다. 이름은 그 화살표의 바깥쪽 법선 방향으로 계산해 둔다.
- 세포 소기관이 막과 벽을 뚫고 나오면 안 된다(사용자 지적). `lib/cell.js`의 `placer`가 막 안쪽 다각형과 서로의 거리를 함께 본다.
- 투명한 물체(transmission)끼리는 서로를 못 본다. 병 속 물, 대롱 속 잉크처럼 속에 든 것은 불투명하게, 겉 유리는 opacity로 하고 `userData.noEdge`(윤곽선 계산에서 뺀다).
- 직접 짠 관 기하(굵기가 바뀌는 관)는 삼각형 감김이 안쪽을 보면 앞벽이 잘려 뒤가 비친다(u2l5f2에서 식도가 위를 뚫고 보였다). 감김은 바깥 법선이 나오게.
- 투명한 반구(천구) 앞면의 길은 땅 위에 그린 선처럼 읽히기 쉽다. 사진기를 낮게(14°) 두고, 앞면 길에 흰 테, 뒷면 길은 옅게, 유리 가장자리를 짙게 했다.
- 고리 질감(`saturn_ring.png`)은 가로가 반지름 방향이다. RingGeometry의 UV를 반지름으로 다시 매기고, 카시니 간극 자리로 안팎 반지름을 맞춘다(1.176~2.327 R).
- 고리가 토성 몸에 드리운 그림자는 몸 아래가 잘린 것처럼 보였다. 몸 → 고리 그림자만 둔다.
- 별 자취에서 따뜻한 색 자취가 주황 화살표와 헷갈렸다. 자취의 따뜻한 색은 옅게, 개수도 줄였다.
- 화살표가 닿은 점을 덮으면 손이 물체에서 떨어져 보인다(u5l4f1). 닿는 쪽 물체를 화살표보다 크게.
- 투명한 유리(관, 병)는 흰 바탕에서 사라진다. 빈 부분과 테두리는 SVG로 긋는다(u3l5f1, u3l4f1, u4l4f2). 양면 유리 두 겹은 속을 하얗게 덮으니 앞면 한 겹으로.
- 힘 화살표와 같은 색의 물체(초록 컨테이너)는 화살표를 묻는다. 그림 안 물체 색에서 화살표 색을 뺀다.
- 그림을 고친 뒤에는 처음 보는 에이전트에게 다시 보인다. 이번 검수에서 그린 세션이 못 본 결함 열 가지가 나왔다(output/sci-figures/g1/README.md).
- 긴 heredoc은 잘린다. 고칠 글은 파이썬 스크립트 파일로 바꾸고, 윈도 콘솔(cp949)로 한글을 찍지 말고 UTF-8 파일로 써서 읽는다.
- 정리 카드는 카드 어디를 눌러도 접힌다. 그림을 눌러 크게 보려다 카드가 접힐 수 있다(아래 제안).

## 2026-11-22 다시 그린 세 장(구도를 새로 잡음)

다른 그림을 닮지 않도록 구도와 소재를 새로 잡았다. 그림마다 자세한 사실과 수치는 `figs/<키>.md`.
세포 두 장(u2l2f1, u2l2f2)은 윗부분을 잘라 속을 보이는 흔한 표준 도해라서 사용자 판단으로 그림을 그대로 두었다(메모의 출처 표기만 정리했다).

- **u3l3f1 열의 이동**: 부엌 조리대의 가스 불, 그 위의 긴 금속 손잡이 냄비(손잡이를 따라 전도, 잘라 보인 물속의 대류), 불 옆에 세운 온도계(복사). 사람의 손과 팔은 그리지 않는다. 이름 밑 보조 글은 레슨 분류 문제의 힌트와 같은 말.
- **u4l4f1 상태 변화와 입자 배열**: 크기가 같은 밀폐 유리그릇 셋을 정삼각형 자리에(위 기체, 왼쪽 아래 고체, 오른쪽 아래 액체), 입자는 청록 18개씩. 부피는 그릇 안에서 입자가 차지한 자리(고체 덩어리, 액체의 낮은 층, 기체는 그릇 전체).
- **u5l7f1 힘과 운동**: 나뭇가지에 매달린 사과(가지가 당기는 힘과 중력의 평형)와 가지에서 떨어진 사과(중력만, 같은 시간 간격 네 자리, 간격 1 : 3 : 5 : 7, 운동 방향 화살표 1 : 2 : 3 : 4).

그릴 때 걸렸던 것:
- 기체 입자를 무작위로 흩으면 몇 쌍이 너무 가까워진다. 후보 여럿 가운데 가장 먼 자리를 고르고 몇 번 밀어내 간격을 고르게 한다(최소 간격을 코드가 확인).
- 곧게 떨어지는 물체는 중력 화살표와 운동 방향 화살표가 같은 세로선에 겹친다. 힘은 가운데 점에서, 운동 방향은 곁에 따로 그린다. 중력 화살표 끝이 다음 자리의 물체에 닿지 않는지 코드가 확인한다.

## 확인

```
npx tsc --noEmit
npm run build
NODE_ENV=development npx vite build --mode development --outDir <폴더> --emptyOutDir
DIST=<폴더> node qa/scifig-g1/check-app.mjs [캡처 폴더] [키...]      # 또는 PORT=<개발 서버 포트>
```
check-app은 그림이 실린 스텝까지 걸어가(정리 카드는 펼쳐서) 그림이 뜨는지, `loading="lazy"`가 없는지, 페이지 오류, 그림 높이가 스크롤 영역을 넘는지 본다. 대상은 단원 글에서 `scifig/g1/` 경로를 찾아 자동으로 고른다.
과학 검산과 눈검수는 그린 세션이 아니라 다른 에이전트에게 그림과 참고 자료만 주고(메모와 코드는 주지 않고) 맡긴다.

## 제안(공용 기능이라 만들지 않았다)

- 눌러서 크게 보기: 정리 카드 안의 그림을 누르면 카드가 접힌다. 그림만 눌렀을 때 화면 가득 보여 주는 공용 보기(그리고 카드 접힘 막기)가 있으면 좋다.
- `dsl.ts`의 `rimg()`가 `loading="lazy"`를 단다(아트 파이프라인 규칙과 어긋남).
- 이 브랜치가 글에서 뺀 생성 그림 넷(`public/recap/u7-phase-map.webp`, `u7-star-trails.webp`, `u4-ice-lattice.webp`, `u5-friction-zoom.webp`)은 이제 아무도 쓰지 않는다. 병합 뒤 지워도 된다.
- `public/photos/CREDITS.md`에 "public/scifig/g1 도해가 public/textures(Solar System Scope, CC BY 4.0)와 sun_whitelight.jpg(NOIRLab, CC BY 4.0)를 쓴다"는 줄을 더한다(공용 파일이라 손대지 않았다).
