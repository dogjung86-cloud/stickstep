    3×4 + 4×2`라 매 응시에 레슨당 3~4문항이 나간다. 특정 레슨 풀이 얇아지면 그 레슨의 같은 문항이
    상시 출제돼 **파트별 진단 품질이 직접 무너진다**(u2 재매핑 사고의 교훈). 계보 가중은 슬롯 수가

    그대로 옮기면 실측보다 과대해진다 — mcq 용어 동정형이 흡수한다.

    동화 작용 · 유기물 · 탄수화물 · 총광합성량 · 겉보기광합성량 · **분자** · 화학 반응식 표기
    (6CO₂ · C6H12O6 등 아래첨자 수식) · ⭕.
    - 오탐 주의: "보상"은 "보상 상태/보상점"만 금지어로 잡고 다른 문맥에 쓰지 않는다(스캔은 부분열).
      "효소"는 온도 곡선 해설의 유혹이 크지만 **레슨이 "반응을 돕는 단백질의 기능"으로 우회**했으므로
      해설도 "너무 높은 온도에서는 광합성을 돕는 과정이 방해받는다"로 서술한다.
- **광합성·호흡 검산 세트(전 슬롯 저작 주석 병기 — 위반 시 실격)**
  1. 광합성 = 빛에너지로 **이산화 탄소 + 물 → 포도당 + 산소**, 장소 = **엽록체**.
     **빛은 에너지원이지 재료가 아니다**(반응물 칸에 빛을 넣는 보기는 오답 미끼로만).
  2. 아이오딘 반응은 **녹말** 검출(청람색)이지 포도당이 아니다. 잎 실험은 **암처리 선행**(기존 녹말
     제거) + **에탄올 탈색**(엽록소 제거) 순서가 고정이며, 뜨거운 물 중탕을 쓰는 까닭(에탄올은 불이
     붙기 쉽다)까지 검산한다. 절차 = 뜨거운 물 → 에탄올 중탕 → 물로 헹굼 → 아이오딘 용액.
  3. 광합성 산물 포도당은 잎에서 **녹말**로 저장되고, **주로 밤에 설탕**으로 바뀌어 **체관**으로
     이동한다(물관 아님).
  4. **물관 = 뿌리→잎 물·무기 양분 상승(한 방향)** / **체관 = 양분 이동(필요한 기관을 향해
     위·아래 양방향)**.
  5. 기공은 **공변세포**가 둘러싼 잎 표면의 구멍이다. **"잎 뒷면에 많다"는 레슨 미도입이라 문두
     단서로 제시하지 않는 한 정답 근거로 쓰지 않는다.**
  6. 요인 곡선: 빛 세기↑·CO₂ 농도↑ → 어느 지점부터 **일정** · **온도는 알맞은 온도까지 증가 후
     감소**("높을수록 유리"는 항상 거짓 미끼).
  7. **호흡은 낮·밤 모두 계속된다.** 낮에는 광합성량 > 호흡량이라 겉보기로 산소를 내보내는 것처럼
     보인다.
  8. **겉보기 기체 출입 0 = 광합성량 = 호흡량**(새벽·해 질 무렵). "광합성을 하지 않는 상태"가 아니다.
  9. 광합성은 **엽록체가 있는 세포**, 호흡은 **살아 있는 모든 세포**에서 일어난다.
  10. 광합성 = 에너지 **저장**, 호흡 = 에너지 **방출**(생활 에너지). 두 반응의 기체·물질 방향은
      서로 반대지만 **장소·조건·에너지 방향이 달라 완전한 역과정이 아니다**.
  - **3사 표기 대조 결과**: 이동 형태는 3사 모두 **"설탕"**(수크로스 미사용) · 호흡 장소는
    **"마이토콘드리아"**(미토콘드리아 표기 혼재하나 레슨 정본이 마이토콘드리아) · 검출 색은
    **"청람색"**. 우리 표기는 전부 레슨 정본과 일치한다.

   시간–기체 농도 곡선. **눈금 수치 미인쇄(정성)** — 3사 실측 그대로. 구간 표지 ㉠~㉢ 지원 ·
   가이드 점선 금지(g2u2 ② 계보) · `hideAxis`는 축 라벨 역추론 문항용(비상 08 계보).
5. **EX** `sealedPlantFig(o: { panels: { plant: "live" | "boiled" | "none"; cover: "none" | "foil" | "dark"; label: string }[] })`
   밀폐 용기 + 식물 + 센서 장치 패널(2~3컷). **조건 이름은 라벨로 인쇄하지 않는다**(판독 과제 보존 —
   패널 라벨은 (가)(나)(다)뿐).
6. **FC** `factorGraphFig(o: { kind: "sat" | "peak"; curves: { label?: string; scale?: number }[]; xLabel?: string; yLabel?: string; marks?: string[] })`
   요인–광합성량 곡선. `xLabel` 생략 = 축 라벨 가림(역추론) · `curves` 2개면 겹침 비교(제한 요인
   전환점) · 구간 표지 ㉠~㉢. **정성 곡선(눈금 수치 없음)**.
7. **DN** `dayNightGasFig(o: { panels: { light: "bright" | "dim" | "none"; inGas: "co2" | "o2" | null; outGas: "co2" | "o2" | null; label: string }[] })`
   낮/밤 겉보기 기체 출입 2패널. **기체 이름 칩을 화살표 옆에 인쇄**(dayNightFlowFig의 범례 부재
   결함의 수정) · **결론 캡션 없음** · aria는 패널 라벨과 밝기까지만 서술.
8. **GB** `rateBarsFig(o: { groups: { label: string; photo: number; resp: number }[]; showValues?: false })`
   시각·조건별 **광합성량 / 호흡량 막대 쌍**. 값 라벨은 인쇄하지 않는다(높이 판독이 과제) ·
   두 막대 높이가 같은 그룹은 "겉보기 출입 0" 판정의 근거가 된다.
9. **TR** `transportRouteFig(o: { syms: { route: "xylem" | "phloem-up" | "phloem-down" | "phloem-fruit"; sym: string }[]; sinks?: ("bud" | "fruit" | "root")[]; wrongArrow?: string })`
   물관·체관 이동 경로도. **물관 화살표는 반드시 뿌리 끝에서 시작**하고, 라벨은 **지시선 달린 배지**로
   그린다(transportFig 두 결함의 수정) · 갈래는 파라미터로 켜고 끈다(겹침 방지).

### 5-2. 재사용 4종
- `svgTable(head, rows, { firstColHead })` — 비교표·조건표·결과표. **2열 기준 한글 ≤ 13자 ·
  3열 기준 ≤ 8자**(u1 v2 §14 ①). **같은 표를 두 문항이 쓰면 한쪽이 shuffle:false answer 0이 되므로
  표를 벌수로 분리한다**(g2u8 v2 관행).
- `dbox(rows)` — 자료 상자(사례 서술·실험 조건·관찰 기록). 원자료 문두 나열의 대체 그릇.
- `variableTableFig({ items, marks })` — **u1 v2 섹션 재사용**. 조건 × 같게/다르게 배정 표(`q` = ㉠ 빈칸).
  **조작 변인은 언제나 1행만 diff**(과학 규칙 검산).
- `inquiryFlowFig({ steps, blank })` — **u1 v2 섹션 재사용**. 세로 상자 사슬 + 빈칸 ㉠. 절차(아이오딘
  검출)·전환 사슬(포도당 → 녹말 → 설탕 → 체관)에 쓴다. **상자 텍스트 한글 ≤ 7자** · `loop`는 쓰지
  않는다(탐구 전용 라벨 "고쳐서 다시"가 붙는다).

## 8. 저작·검증 체크리스트 (파일럿·확대 공통)

1. **자료 의존 검산** — 그림·표·자료 상자를 가리고 문항을 읽었을 때 답이 나오면 장식이다. 장식이면
   자료를 빼고 무자료 화이트리스트로 재분류하거나 과제를 판독으로 바꾼다.
2. **교차 유출 스캔(이 단원 1순위 위험)** — 같은 **데이터 세트**를 두 문항이 나눠 쓰면 뒤 문항의
   자료가 앞 문항의 정답을 인쇄한다(u1 v2 §14 ①). 특히 위험한 군집:
   같은 대조 실험(EX 패널) · 같은 곡선 세트(FC) · 같은 비교표(TB) · 같은 도해(PS/DN/TR) ·
   같은 사진 2문항. **헬퍼 군집은 데이터 세트 단위로 배타 배정**하고, 저작 직후 메인이 1차 대조 ·
   검산 에이전트가 2차로 훑는다.
3. **사진 alt는 "무엇이 찍혀 있는가"까지만** — 판정 결과(밝다·많다·변했다)를 적으면 정답 낭독.
   **같은 사진은 질문 축까지 배타**(장당 2문항 상한만으로는 유출을 못 막는다 — u1 v2 §14 ②).
4. **합답형은 ㄱ의 진위까지 분산**(조합만 흩는 것으로 부족) · **multi는 정답 개수(2~3)도 흩는다**.
5. **해설의 보기 위치 지칭 금지**("첫/두 번째/마지막 보기") — 저작 습관이라 반드시 재발한다.
   수정 뒤 check를 다시 돌린다.
6. **파일럿에서 고친 수정은 확대분에 반드시 소급**(u1 v2 §14 ③).
7. **그림 aria는 파라미터 파생** · 같은 값이 겹칠 수 있는 헬퍼는 라벨 분리를 헬퍼가 보장.
8. **공유 파일 생성기는 마커 구간만 교체 + 첫 실행 뒤 즉시 tsc**("마커 이후 전부" 패턴 금지 —
   u1 v2 §13 실사고: examFigures.ts에서 타 세션 헬퍼 33종을 삼켰다).
9. **§2 앵커 금지는 §3 슬롯 표보다 우선**한다.
10. 문항 **자기완결**(이웃 문항 참조 금지) · 순서도는 분기마다 결론 칸이 갈릴 것 ·
    svgTable 셀 한도(2열 한글 ≤13자 · 3열 ≤8자) · 해설 250~450자 + `<span class='xh'>` 2단 + core 한 줄.
11. **소스 일괄 치환은 node/Edit로만** — PowerShell `Get-Content -Raw`는 BOM 없는 UTF-8을 CP949로 읽어
    한글을 비가역 파괴한다(u5 v2 ⑤ · g2u3 v2 §8-8b 실사고).
12. **기호로 물은 것은 해설에서 이름을 돌려준다**(사용자 지적 2026-08-02 · §13). 그림이 ㉠~㉤으로
    부위를 가리키면 해설은 **정답 부위와 오답 부위 모두 레슨 도입어로 명명**해야 한다. "작은 틈"·
    "굵고 둥근 관"으로만 부르고 끝내면 학생은 답을 맞히고도 그게 기공인지 모른 채 나간다.
    검사 = `node qa/scan-g2u5-terms.mjs`(돌려 말하기 표현 ↔ 도입어 대조 · 그래프의 구간 표지는 제외).

## 14. 화살표 실사용 피드백 3건 (2026-08-02 · 사용자 지적 2차)

### 14-1. 화살촉이 선 굵기에 비례해 커지는 구조 결함 (2번·22번·27번 = 슬롯 203·282·294)
`<marker>`의 `markerUnits` 기본값은 `strokeWidth`다. 그래서 굵기 4.6 화살에 markerWidth 6.4를 주면
**화살촉이 약 29px**이 되어, 28px짜리 물질 화살표는 몸통이 통째로 화살촉에 먹혔다("화살표 선이 잘
안 보인다"). 그림이 커질수록 더 심해지는 함정이라 확대분 전체에 걸린다.
- **수리**: `arrowDefs(id, color, size = 12)`에 **`markerUnits="userSpaceOnUse"`** 를 넣어 화살촉 크기를
  선 굵기에서 분리했다. 굵기도 함께 낮춤 — PS 4.6 → **3.2**(촉 12) · DN 4.8 → **3.6**(촉 14) ·
  TR 5.4 → **3.8**(촉 14). PS 화살표는 길이도 96~124 → **94~126**으로 늘려 몸통을 확보.
- **관행**: **화살촉 크기는 선 굵기와 분리해 고정한다(`userSpaceOnUse`)**. 화살표 몸통이 화살촉보다
