## 2. 파이프라인 (4단계)

```
① capture.mjs   앱을 헤드리스로 실제 조작하며 스크린캐스트 → cap/<beat>/f*.jpg + times.json
② rebuild-beats.mjs   cap/ → beats-raw/*.mp4 (자막·손가락 없는 원속 영상, 30fps CFR)
③ compose.mjs   beats-raw를 폰 목업 안에서 배속 재생하며 재촬영 → cap2/c-*/
④ assemble2.mjs  cap + cap2 → beats2/*.mp4 → 밴드 분할 전환 연결 → BGM+효과음 → out/stickstep-marketing-9x16.mp4
```

④는 `audio/*.mp3`(BGM 2곡+효과음 5종)가 있어야 돈다 — 없으면 `XI_KEY=<키> node gen-audio.mjs`로
1회 발주(있으면 skip, 재발주는 해당 mp3 삭제 또는 --force. 키는 env로만 — 리포 저장 금지).

`make-gifs.mjs`는 ② 뒤에 언제든 돌릴 수 있다(beats-raw에서 다크 무대만 크롭 → out/gifs/, 아래 §5).
`check-safezone.mjs`는 ④ 뒤에 돌린다(인스타 세이프 존 기계 판정 — 위 §1 규격, 실패 시 exit 1).

## 3. 반드시 알아야 할 함정 (전부 실사고)

1. **1080×1920은 뷰포트 405×720 × deviceScaleFactor 8/3**로 만든다. CDP `Page.startScreencast`가
   그대로 1080×1920을 뱉는다.
2. **스크린캐스트는 가변 프레임**(정지 구간엔 프레임이 안 온다). `times.json`의 실측 타임스탬프를
   30fps로 리샘플하되 **concat demuxer를 쓰지 말 것** — jpg 고유 1/25s 아래로 duration을 못 줄여
   영상이 늘어난다(2회 사고). 정답은 하드링크로 CFR 시퀀스를 물질화 후 `image2`(rebuild-beats 참조).
3. **CSS 연출은 페이지 로드 순간 시작되는데 녹화는 그 뒤에 시작**돼서 앞 1초가 잘린다.
   → 연출 페이지 전부(`intro/endcard2/compositor`)에 `animation-play-state: paused` +
   `body.go` 게이트를 두고, **rec.start 뒤에** 게이트를 발사한다.
4. **slideup만 켜면 오히려 어색하다.** 각 비트가 "빈 무대 → 폰 rise → 텍스트"로 시작해
   슬라이드 인 직후 빈 화면이 보이는 이중 전환이 된다. → compositor의 `__reveal()`(등장)과
   `__go(rate)`(영상 재생)를 분리하고, compose가 `__reveal → 1.45s 대기 → rec.start → __go`
   순서로 찍어 **완성된 카드가 통째로 슬라이드 인**하게 한다.
5. **헤드라인에 `word-break: keep-all` 필수** — 없으면 "정/복해요"처럼 음절이 꺾인다.
6. **엔드카드 발자국 opacity 하한은 .55** — 스플래시(밝은 배경)의 .3 램프를 그대로 쓰면
   다크 배경에서 갈색 진흙으로 죽는다.
7. **만화·퀴즈 비트는 레슨 미완료 상태로 찍는다** — 완료 레슨은 첫 스텝 CTA에
   "완료한 레슨이에요…" freeNav 배너가 뜬다(랩은 fwd 이동 뒤라 무해).
8. **스플래시 하단에 사업자 정보(전화번호)가 노출**된다 → 브랜드 컷은 스플래시를 찍지 말고
   `endcard2.html`을 쓴다.
9. **시험 비트는 `examScreen("u3")` 직접 진입**으로 찍는다. 지도 노드 탭 경유는
   홈 스텁 콜백이 no-op이라 동작하지 않는다.
10. 걷기 연출은 `homeScreen(..., { walkFrom })` 직접 렌더로 트리거한다
    (`completeLesson` 후 `nav.reset`). 걷기 1회 = 고정 2.1초.
11. 동시 세션이 `src`를 저장하면 HMR 풀리로드로 캡처가 깨진다 →
    capture.mjs가 `@vite/client` 스텁을 물려 둔다(그대로 유지할 것).
12. **xfade 체인 끝엔 `format=yuv420p`를 반드시 명시** — 입력 beats가 전부 420이어도 xfade
    다중 체인은 필터 협상이 4:4:4로 승격해 최종본이 yuvj444p로 인코딩된다(2026-08-06 실사고:
    윈도우 기본 플레이어(하드웨어 디코더)가 4:4:4 미지원이라 **더블클릭하면 녹색 글리치** —
    브라우저는 SW 디코딩이라 멀쩡해 보여 발견이 늦었다). assemble2 edges 단계의 format을
    지우지 말 것. 출하 전 검사 = `ffprobe -select_streams v:0 -show_entries stream=pix_fmt`
    → `yuvj420p`여야 한다(444가 보이면 실격).

## 3.5 GIF 짤 (유튜브 커뮤니티·SNS) — `make-gifs.mjs`

**11종**: heat-particles(분자 운동) · ice-boil(상태 변화) · boyle-syringe(기체 압력) · moon-phase(달 위상 3D) ·
laser-reflect(반사) · color-mix(빛의 삼원색) · molecule(분자 조립) · atom(원자 조립) · wave(파동) ·
**photosynthesis(광합성 — 생물 트랙)** · **exam(단원 종합 평가 풀이 — 2026-08-22, 유튜브 커뮤니티
개발 근황 글용)**.
산출 `out/gifs/*.gif` + `chk-*.jpg`(중간 프레임 눈검수 샷), 로컬 보존은 `output/marketing-video/`.

- **크롭은 자동 검출**(2026-08-05 — 손으로 적어 둔 좌표가 전부 어긋나 있었다: ice-boil은 무대 아래
  흰 앱 UI가 172px 딸려 들어와 4.2MB였고, laser는 반대로 무대 하단이 21px 잘려 있었다).
  `detectCrop()`이 중간 프레임에서 어두운(<70) 픽셀이 행의 절반을 넘는 구간으로 무대 세로 범위를
  잡는다. 랩 레이아웃이 바뀌어도 좌표를 다시 적을 필요가 없다 — 대신 chk 샷을 눈검수할 것.
- **`controls: true`면 무대 아래 조작부까지 포함**(2026-08-05 사용자 지시 "아래 조작하는 버튼 나오는
  부분도 살려야 한다"): 분자 운동·상태 변화는 **슬라이더가 다크 무대 바깥(흰 영역)에** 있어 무대만
  자르면 "뭘 움직여서 저렇게 됐는지"가 사라진다. 무대 아래 **첫 콘텐츠 덩어리**(공백 45px 이상이면
  중단 — 더 내려가면 화면 맨 아래 안내 문구까지 딸려 온다)를 찾아 `PAD`(16px) 흰 프레임으로 감싼다.
  이때는 둥근 모서리를 살린다(하드컷하면 모서리가 잘려 어색하다).
- **`controls` 없는 랩은 무대만 꽉 채워 자른다**(주사기 피스톤·달 궤도·레이저 각도 — 조작이 캔버스
  안에서 일어나 무대가 곧 조작부다): **네 귀퉁이가 모두 무대 안이 될 때까지 인셋**해 둥근 모서리의
  흰 삼각형을 없앤다(실측 inset 22). 두 방식이 섞이는 건 의도 — 랩마다 조작부 위치가 다르다.
- **분자 운동·상태 변화는 왕복**(2026-08-05 사용자 지시): 되돌아오는 구간이 있어야 원리가 읽히고
  루프도 자연스럽다. **본편 비트를 늘리면 카드 길이·러닝타임이 함께 변하므로 GIF 전용 왕복 비트를
  따로 캡처**한다 — `capture.mjs`의 `BEATS.heatrt`(b1r-heat: 차갑게→뜨겁게→다시 차갑게)와
  `BEATS.matterrt`(b2r-matter: 얼음→융해→끓음→융해→다시 얼음). rebuild-beats SEQ에도 등록돼 있고,
  캡처가 없으면 SKIP된다. 되감기(boomerang) 방식은 쓰지 않는다 — 파일이 두 배가 되고 앱의 복귀
  안내 문구("수증기가 다시 물방울로!"·"물이 다시 얼기 시작해요")를 못 살린다.
- **무대 밀림은 크롭 추적으로 고정**(2026-08-05 사용자 지적 "우주 3d 막판에 화면이 살짝 내려간다"):
  랩이 목표를 달성하면 안내문이 한 줄 늘었다 줄었다 하거나(리플로우) 판정 질문이 뜨며 스크롤돼
  무대가 통째로 밀린다. 검사를 붙여 보니 **달만이 아니라 레이저(−470px 스크롤)·분자(±59px ×3)·
  열·파동(+56px)에도 같은 결함**이 있었다. `stageTrack()`이 0.25s 간격으로 무대 위치를 훑고
  전환 시각을 이분 탐색으로 좁힌 뒤, ffmpeg crop의 y를 `if(lt(t,T),y0,y1)` 중첩식으로 줘
  **프레임마다 무대를 따라가게** 한다(구간을 버리지 않으므로 길이 손실 0). 밀림 횟수는 실행 로그에 뜬다.

  돈다** — GIF는 스스로 도는 랩이라야 루프가 산다. **`반응로`·`저장`은 누르지 말 것** — 밸브를 닫아 흐름이 멈춘다.

  생기고 순서대로"): 재료 0/3(빈 잎) → 물관 열림(물방울) → 기공 열림(CO₂) → 빛 열림(광자·포도당·산소,

- **exam GIF = `BEATS.examgif`(bEr-exam) + make-gifs `full: true` 크롭 모드**(2026-08-22): 시험 화면은

  bE-exam은 evaluate 즉발 클릭 2문항이라 GIF 호흡이 없고, 본편을 늘리면 카드 길이가 변하므로 전용
  비트. 왕복 비트와 같은 이유). 유형 무관 자동 응답(opt는 문항마다 다른 보기·chip 첫 칩·num은
